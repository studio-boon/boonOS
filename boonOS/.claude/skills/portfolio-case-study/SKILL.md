# portfolio-case-study

Transforme projeto visual em narrativa de valor sem inflar o que aconteceu.

## Briefing

Coletar:

- nome do projeto;
- cliente ou contexto;
- papel do designer;
- problema inicial;
- restrições;
- processo;
- entregáveis;
- resultado ou aprendizado;
- imagens disponíveis;
- público do portfolio.

## Estrutura recomendada

```text
1. Contexto
2. Problema
3. Papel no projeto
4. Direção tomada
5. Processo e decisões
6. Sistema visual ou solução
7. Resultado
8. Aprendizados
```

## Critérios

- Mostrar decisão, não só estética.
- Separar o que o designer fez do que a equipe fez.
- Evitar prometer impacto sem prova.
- Usar imagens como evidência do raciocínio.
- Cada seção precisa responder "por que isso importa?".
- Aplicar a skill writing-filter antes da versão final.

## Saída padrão

```markdown
## Título do case
[nome + síntese]

## Abertura
[contexto e problema]

## Papel
[responsabilidade real]

## Decisões principais
- ...

## Estrutura da página

## Texto final
[copy organizada por seção]
```
