# Comece aqui

Este sistema não precisa nascer perfeito. Ele só precisa começar com uma primeira situação real.

## 1. Abra no Codex

No Codex Desktop, abra a pasta deste repositório. No terminal, entre na pasta e execute codex.

## 2. Faça a entrevista inicial

Escreva $init. Se preferir, basta copiar esta primeira mensagem:

~~~text
Acabei de clonar o boonOS. Me guia na instalação e faz o onboarding comigo.
~~~

O próprio Codex encontra a skill init e conduz a entrevista.

O agente vai perguntar em blocos curtos, pode pausar e só grava o resultado quando você aprovar. Você escolhe o nome do seu sistema e a trilha que faz mais sentido agora.

## 3. Escolha uma primeira missão

Para quem está estudando criação e design, boas primeiras missões são:

- analisar uma peça que admira com $design-review;
- transformar uma referência em aprendizado com $study-playbook;
- criar um cartaz, post ou capa com $design;
- transformar uma ideia em slides com $presentation;
- montar um mini-case de portfolio com $portfolio-case-study.

Não tente organizar a vida inteira no primeiro dia. Faça uma coisa, registre o que decidiu e volte amanhã.

## 4. Onde cada coisa mora

| Se você tem... | Guarde em... |
|---|---|
| trabalho em andamento | 00. TRABALHO/ |
| uma regra ou decisão que deve durar | 01. SISTEMA/ |
| algo que o sistema precisa lembrar depois | 02. MEMORIA/ |
| aula, briefing ou fonte que pode ser versionada | 03. DOCS/ |
| contrato ou documento confidencial local | 03. DOCS/_PRIVADO/ |
| algo encerrado que não quer apagar | 99. OLD/ |

## 5. Uma regra que evita bagunça

Antes de criar uma pasta ou arquivo novo, pergunte: isto é trabalho ativo, sistema, memória, documento ou arquivo? Se ainda não estiver claro, deixe como rascunho na pasta do projeto e decida depois.
